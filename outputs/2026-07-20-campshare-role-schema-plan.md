# CampShare Role Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Flywayの明示的なSQLマイグレーションで`roles`テーブルと基本ロールを安全に作成し、実DBテストで検証する。

**Architecture:** HibernateのDDL自動変更は引き続き`none`のままにする。Flywayが`V1__create_roles.sql`を一度だけ実行して、`roles`テーブル、`ROLE_USER`、`ROLE_ADMIN`を作成する。JPA EntityやRepositoryはこの計画では作成せず、次の小計画に分離する。

**Tech Stack:** Java 17、Spring Boot 3.5.16、Maven Wrapper、PostgreSQL 16、Spring JDBC、Flyway、JUnit 5、AssertJ。

## Global Constraints

- Javaは17、Spring Bootは3.5.16を使用する。
- Windowsではプロジェクト内の`mvnw.cmd`だけを使う。
- DB接続情報は`application-local.properties`だけに置き、Git管理しない。
- HibernateのDDL自動実行は`spring.jpa.hibernate.ddl-auto=none`を維持する。
- この計画で作成・変更するDBオブジェクトは`flyway_schema_history`と`roles`だけである。
- `V1__create_roles.sql`は一度適用した後に変更しない。変更が必要になった場合は次のバージョン番号のSQLファイルを追加する。
- MyBatis、Spring Security、`users`テーブル、JPA Entity、Repositoryはこの計画の対象外とする。
- `.git`配下の書き込みが拒否されているため、コミットは実行しない。
- 各ステップの確認が成功するまで、次のステップへ進まない。

### Task 3: Flywayでrolesテーブルを作成する

**Files:**

- Modify: `campshare/pom.xml`
- Modify: `campshare/src/main/resources/application.properties`
- Create: `campshare/src/main/resources/db/migration/V1__create_roles.sql`
- Create: `campshare/src/test/java/com/example/campshare/config/RoleMigrationTest.java`

**Interfaces:**

- Consumes: Task 2で確認済みの`campshare` PostgreSQL接続と`application-local.properties`。
- Produces: `public.roles(id BIGINT, name VARCHAR(50))`、および`ROLE_USER`と`ROLE_ADMIN`を持つ初期データ。

- [ ] **Step 1: rolesテーブルがまだないことを示す失敗テストを作成する**

`campshare/src/test/java/com/example/campshare/config/RoleMigrationTest.java`を次の内容で作成する。この時点ではFlyway依存関係とSQLマイグレーションを追加しない。

```java
package com.example.campshare.config;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.test.context.ActiveProfiles;
import org.springframework.test.context.TestPropertySource;

import java.util.List;

import static org.assertj.core.api.Assertions.assertThat;

@SpringBootTest
@ActiveProfiles("local")
@TestPropertySource(locations = "file:./application-local.properties")
class RoleMigrationTest {

    @Autowired
    private JdbcTemplate jdbcTemplate;

    @Test
    void rolesTableContainsDefaultRoles() {
        List<String> roleNames = jdbcTemplate.queryForList(
                "SELECT name FROM roles ORDER BY name",
                String.class
        );

        assertThat(roleNames).containsExactly("ROLE_ADMIN", "ROLE_USER");
    }
}
```

- [ ] **Step 2: テストがrolesテーブル未作成で失敗することを確認する**

Run:

```powershell
$env:MAVEN_USER_HOME = "$PWD\.maven-cache"
.\mvnw.cmd test -Dtest=RoleMigrationTest
```

Expected: `relation "roles" does not exist`を含む`BUILD FAILURE`。この時点ではテーブル未作成のため、期待どおり。

- [ ] **Step 3: Flyway依存関係と初回SQLマイグレーションを追加する**

`campshare/pom.xml`の`<dependencies>`内へ、次の2つを追加する。Spring Boot 3.5.16の依存関係管理を使用するため、`<version>`は書かない。

```xml
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-core</artifactId>
</dependency>
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-database-postgresql</artifactId>
</dependency>
```

`campshare/src/main/resources/application.properties`の末尾に、次を追加する。

```properties
spring.flyway.locations=classpath:db/migration
```

`campshare/src/main/resources/db/migration/V1__create_roles.sql`を次の内容で作成する。

```sql
CREATE TABLE roles (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
);

INSERT INTO roles (name) VALUES
    ('ROLE_USER'),
    ('ROLE_ADMIN');
```

- [ ] **Step 4: Flyway適用後にテストが成功することを確認する**

Run:

```powershell
$env:MAVEN_USER_HOME = "$PWD\.maven-cache"
.\mvnw.cmd test -Dtest=RoleMigrationTest
```

Expected: `BUILD SUCCESS`。Flywayが`V1__create_roles.sql`を一度適用し、`roles`に`ROLE_ADMIN`と`ROLE_USER`があることをテストが確認する。

- [ ] **Step 5: pgAdminでDB変更を確認する**

pgAdminのQuery Toolで次を実行する。

```sql
SELECT id, name
FROM roles
ORDER BY name;

SELECT version, description, success
FROM flyway_schema_history
ORDER BY installed_rank;
```

Expected: 最初のSQLは`ROLE_ADMIN`と`ROLE_USER`の2行を返す。2つ目のSQLは`version = '1'`、`description = 'create roles'`、`success = true`の行を返す。

- [ ] **Step 6: 全テストと既存トップページを確認する**

Run:

```powershell
$env:MAVEN_USER_HOME = "$PWD\.maven-cache"
.\mvnw.cmd test
.\mvnw.cmd spring-boot:run
```

Expected: テストは`BUILD SUCCESS`。ブラウザで`http://localhost:8080/`を開くと、`CampShare`と`キャンプ用品を、もっと手軽に。`が表示される。確認後、起動ターミナルで`Ctrl + C`を押して停止する。

次へ進む前に、ユーザーが以下を確認する。

1. Step 2で`roles`未作成による失敗を確認した。
2. Step 4でFlyway適用後のテスト成功を確認した。

成功した場合のみ、ユーザーは「Task 3成功」と報告する。報告があるまで、User Entity、Role Entity、Repository、認証、商品テーブルの実装を開始しない。
