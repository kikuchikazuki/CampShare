# CampShare Task 7: 予約・在庫・マイページ設計

## 目的

ログイン済みの利用者がキャンプ用品を1点ずつ予約でき、予約完了と同時に在庫を減らす。予約履歴は本人だけがマイページで確認できるようにする。

## 範囲

- 商品詳細画面と、そこから開く予約フォーム
- 開始日・終了日を指定する1点予約
- 在庫数の安全な減算と予約レコードの保存
- ログインユーザー本人の予約履歴

決済、キャンセル、返却、複数商品のカート、期間重複に応じた在庫計算は今回の対象外とする。

## データ設計

Flywayの `V4__create_rentals.sql` で `rentals` テーブルを追加する。

| 列 | 内容 |
| --- | --- |
| `id` | 予約ID（主キー） |
| `user_id` | 予約したユーザー。`users.id` を参照 |
| `gear_id` | 予約した用品。`gears.id` を参照 |
| `start_date` | 利用開始日 |
| `end_date` | 利用終了日。開始日より後の日付が必要 |
| `total_price` | 料金。`終了日 - 開始日` 日数 × 日額 |
| `status` | 今回は常に `RESERVED` |
| `created_at` | 予約作成日時 |

料金計算では終了日を返却日として扱う。たとえば8月1日から8月3日までは2日分として計算する。

## 画面と認可

1. 一覧の各商品から商品詳細へ移動する。
2. 商品詳細には「予約する」リンクを表示する。未ログインなら既存のSpring Security設定によりログイン画面へ遷移する。
3. ログイン済みなら、開始日・終了日を入力する予約フォームを表示する。
4. 予約に成功したら `/mypage/rentals?reserved=true` へリダイレクトし、完了メッセージと履歴を表示する。
5. マイページには、ログイン中の本人の予約だけを新しい順で表示する。

`/mypage/**` と予約用URLは既存の「それ以外は認証必須」の設定に従う。管理者専用の機能は含めない。

## 在庫の整合性と例外処理

予約処理は `@Transactional` のサービスに置く。対象用品をPostgreSQLの悲観ロック付きで取得し、在庫が1以上であることを確認してから、在庫を1減らし予約を保存する。

このため、同じ最後の1点を同時に予約しようとした場合も、片方だけが成功する。対象商品がない場合は404、在庫が0の場合と日付が不正な場合は予約フォームにエラーメッセージを返す。失敗時は在庫変更・予約保存を行わない。

## コンポーネント分割

- `Rental` / `RentalRepository`: 予約データの永続化と本人の履歴検索
- `RentalService`: ログインユーザーの特定、日付・在庫の検証、料金計算、トランザクション処理
- `GearRepository`: 予約処理専用の悲観ロック付き用品取得
- `GearDetailController`: 商品詳細と予約フォームの表示
- `RentalController`: 予約登録とマイページ表示
- `RentalForm`: 入力値の受け渡しと入力エラー表示

## テスト方針

- 予約サービス: 在庫ありなら予約保存・在庫減算・正しい料金計算、在庫0なら保存しない、日付不正なら保存しない。
- Web層: 未認証の予約URLはログインへ誘導、認証済みでフォームと本人の履歴を表示する。
- DB移行: `rentals` テーブルが作成され、必要な列と外部キーを持つことを確認する。

## 完了条件

- ログイン済みユーザーが用品1点を日付指定で予約できる。
- 予約成功後に在庫数が1減り、マイページに予約が表示される。
- 在庫0と不正な日付では予約できない。
- 未ログインでは予約できずログイン画面へ遷移する。
