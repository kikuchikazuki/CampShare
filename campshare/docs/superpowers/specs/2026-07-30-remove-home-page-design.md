# ホームページ廃止と共通ヘッダー導入 設計

## 目的

独立した `home.html` を廃止し、利用者がルート URL へアクセスした時点で用品一覧へ移動できるようにする。ホームページにだけ存在するナビゲーションと認証状態の表示は共通ヘッダーへ移し、各画面から主要機能へ直接移動できる構成にする。

## 画面遷移

- `GET /` は `GET /gears` へリダイレクトする。
- 用品一覧の正式な URL は引き続き `/gears` とする。
- `home.html` は参照されなくなるため削除する。
- 各画面にある「CampShareトップへ戻る」リンクは、共通ヘッダーのブランドリンクまたは用品一覧リンクへ置き換える。

## 共通ヘッダー

共通ヘッダーは Thymeleaf フラグメントとして定義し、通常画面と管理画面から再利用する。

常に表示する項目:

- ブランド名 `CampShare`。リンク先は `/gears`。
- 「用品一覧」。リンク先は `/gears`。

未ログイン時に表示する項目:

- 「ログイン」。リンク先は `/login`。
- 「新規登録」。リンク先は `/signup`。

ログイン時に表示する項目:

- ログイン中ユーザーのメールアドレス。
- 「予約履歴」。リンク先は `/mypage/rentals`。
- POST 送信による「ログアウト」。

管理者だけに表示する項目:

- 「商品管理」。リンク先は `/admin/gears`。

ヘッダーはデスクトップでは横並び、狭い画面では折り返して操作項目が画面外へ出ないようにする。既存の配色変数と Bootstrap のスタイルを利用し、新しい JavaScript は追加しない。

## 認証情報

各テンプレートで個別にモデル属性を設定せず、Thymeleaf から Spring Security の認証状態と権限を参照できる共通方式を使う。必要な連携が未導入の場合は、共通のコントローラー属性として認証情報を提供する。どちらの場合も、表示制御を共通ヘッダー内に集約する。

ログアウトは既存どおり POST とし、CSRF 保護を維持する。

## 対象範囲

- ルート URL のリダイレクト
- `home.html` の削除
- 共通ヘッダーフラグメントの追加
- 既存テンプレートへの共通ヘッダー適用
- ヘッダー用スタイルの追加
- 既存のトップページ向けリンクの整理
- リダイレクト、表示制御、主要リンクを確認するテスト

用品の検索、絞り込み、データモデル、予約処理、管理機能そのものは変更しない。

## 検証

- `/` が `/gears` へリダイレクトする。
- 未ログイン時はログインと新規登録が表示され、認証済み専用項目は表示されない。
- 一般ユーザーには予約履歴とログアウトが表示され、商品管理は表示されない。
- 管理者には商品管理が表示される。
- ログアウトが GET ではなく POST で送信される。
- 主要テンプレートが共通ヘッダーを含んだ状態で正常に描画される。
- モバイル幅でリンクやボタンが画面外へはみ出さない。
